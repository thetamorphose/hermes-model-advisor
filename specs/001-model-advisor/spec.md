# Спецификация: Советник по моделям Nous

Задача: `task-2026-10-17-001`. Источник требований: `docs/history/ТЗ_v0.5.md` (утверждено владельцем). Термины — по `docs/constitution.md`; здесь они не переопределяются.

## Intent

Мы считаем, что портативный скилл-советник, который берёт каталог и цены из API Nous, а оценки — из AA (при его недоступности из LMArena) и ранжирует модели по цене/качеству под задачу пользователя, позволит подписчику Nous Portal за минуту выбрать подходящую модель и увидеть, откуда взята каждая цифра, потому что сегодня каталог из ~426 записей не даёт ни сравнимых оценок, ни понятного выбора под задачу.

_Gate 0: подтверждено владельцем 2026-10-17._

## Правила, которые легко реализовать неверно

Эти пять правил — главный риск ошибки; остальное прямо следует из конституции.

1. **Общий рейтинг — два источника.** Intelligence Index AA; если у модели его нет — Arena overall. Источник виден в каждой строке. Шкалы несопоставимы: нормализация и медиана считаются внутри источника; выдача со смешанными источниками несёт пометку «источники смешаны».
2. **Флагман** выбирается внутри одного источника с приоритетом AA: Arena используется для разработчика только если AA нет ни у одного его семейства. Список: сначала флагманы с AA, затем с Arena. Рядом всегда цена и value.
3. **Резервный режим.** AA недоступен (нет ключа, 401/403, 429, таймаут, сеть, нераспознанный ответ) → сбор оценок не падает, всё берётся из LMArena; у AA в снапшоте оценок `status: unavailable` и код причины; причина попадает в заголовок. Старые значения AA не переносятся. Метрики без аналога в LMArena — «нет данных».
4. **Нет данных ≠ ноль.** Нет уверенного сопоставления имён — «нет данных», а не оценка соседней модели.
5. **Ключ AA** не попадает ни в вывод, ни в логи, ни в снапшот оценок, ни в текст причины ошибки.

## Пользовательские истории

- Как подписчик Nous Portal, я хочу назвать задачу и получить топ моделей по цене/качеству, чтобы не подбирать модель вручную.
- Как подписчик, я хочу видеть источник и дату каждой цифры, чтобы проверять рекомендацию.
- Как подписчик, я хочу обзор рынка: флагманы разработчиков и отдельно свежие и необычно дешёвые модели, чтобы не пропустить нишевые.
- Как подписчик, я хочу сравнить две и более модели в одной таблице.
- Как подписчик, я хочу справку по одной модели: описание на русском, цена, контекст, модальности, оценки, плюсы и минусы из цифр.
- Как подписчик, я хочу, чтобы советник работал и без ключа AA, чтобы не зависеть от платного или недоступного сервиса.
- Как подписчик, я хочу обновлять каталог и оценки одной командой.

## Критерии приёмки

```gherkin
Scenario: AC-1 Каталог и семейства
  Given доступен API Nous и токен
  When запущено обновление каталога
  Then снапшот каталога содержит 400+ записей, цены в $/1M токенов, дубли схлопнуты в семейства
  And представитель семейства — базовый вариант без суффиксов; если цена другого варианта отличается, есть пометка

Scenario: AC-2 Токен Nous
  Given токен не передан аргументом
  When скрипт ищет токен
  Then порядок: аргумент, переменная NOUS_API_TOKEN, auth.json (~/.hermes, $HERMES_HOME, %LOCALAPPDATA%\hermes)

Scenario: AC-3 Оценки при доступном AA
  Given задан ключ AA и API AA отвечает
  When запущен сбор оценок
  Then у каждого значения есть источник, метрика и дата; статус AA — ok
  And если у модели нет значения AA, берётся аналог из LMArena с пометкой источника

Scenario: AC-4 Резервный режим
  Given ключ AA отсутствует, недействителен (401/403), лимит (429) или нет сети
  When запущен сбор оценок
  Then сбор завершается успешно на данных LMArena
  And у AA status = unavailable и код причины без секретов
  And значения AA из прошлого снапшота не перенесены

Scenario: AC-5 Заголовок свежести
  Given существуют снапшоты каталога и оценок
  When выполняется любая команда query
  Then вывод начинается с дат и возраста обоих снапшотов
  And при возрасте старше порога есть подсказка с командами обновления
  And если AA недоступен, заголовок называет причину и сообщает, что оценки из LMArena

Scenario: AC-6 Подбор по категории с прямым бенчмарком
  Given есть оценки по coding
  When recommend --task coding
  Then топ-N по value; рядом исходные значения, источник и дата
  And в ранжировании только модели выше медианы качества категории (порог в конфигурации)

Scenario: AC-7 Подбор по категории без прямого бенчмарка
  Given категория business_spec
  When recommend --task business_spec
  Then заголовок и каждая строка помечены «оценка по общему рейтингу»
  And колонка называется «Общий рейтинг», не «Качество»

Scenario: AC-8 Категория budget
  When recommend --task budget
  Then модели выше порога общего рейтинга ранжируются по цене, value не применяется

Scenario: AC-9 Смешанные источники
  Given в выдаче есть модели с рейтингом AA и модели с рейтингом Arena
  When формируется ранжирование
  Then нормализация идёт по каждому источнику отдельно, источник указан в строке, есть пометка «источники смешаны»

Scenario: AC-10 Флагманы
  When models --set flagships
  Then по одному семейству на разработчика с максимальным общим рейтингом внутри источника (AA приоритетнее Arena)
  And в строке: рейтинг с источником, цена, value, контекст, модальности, описание
  And разработчики без рейтинга перечислены отдельной строкой «нет данных для определения флагмана»
  And в заголовке сказано правило выбора флагмана

Scenario: AC-11 Spotlight
  When models --set spotlight
  Then свежие семейства (порог дней из конфигурации) без дублей и блок «необычно дёшево для своего уровня»
  And только факты: дата релиза, цена, контекст, модальности, описание
  And семейство, попавшее и в флагманы, помечено в обоих списках

Scenario: AC-12 Модель только с Arena
  Given у модели нет AA, но есть Arena overall
  When показывается её карточка или строка
  Then общий рейтинг — значение Arena с пометкой источника, а не «нет данных»

Scenario: AC-13 Сравнение
  When compare A B
  Then таблица: цена in/out, контекст, модальности, оценки по категориям, общий рейтинг; недостающее — «нет данных»

Scenario: AC-14 Справка о модели
  When show <модель>
  Then описание, цена, контекст, модальности, оценки с источниками, плюсы и минусы
  And плюсы и минусы получены правилами из конфигурации, без свободного текста

Scenario: AC-15 Описание на русском
  Given есть перевод описания
  When показывается описание
  Then оно помечено «машинный перевод» и датой
  And если оригинал изменился или перевода нет — показан оригинал

Scenario: AC-16 Целостность
  Given в name_map или переводах есть id, которого нет в актуальном каталоге
  When запуск команды
  Then такие записи помечены устаревшими и не удалены молча

Scenario: AC-17 Воспроизводимость
  Given одинаковые снапшоты и конфигурация
  Then вывод совпадает побайтно

Scenario: AC-18 Лицензии и секреты
  Then в выводе есть атрибуция LMArena (CC-BY-4.0)
  And снапшот оценок с данными AA не входит в дистрибутив и в Git
  And ключ AA не встречается ни в одном выходном файле и логе

Scenario: AC-19 Переносимость
  Given чистый Python 3.10+ без установленных пакетов
  When запущен любой скрипт
  Then он работает; без сети query.py работает на локальных снапшотах
```

## Out of scope

- Ручная курация оценок, ручные правки сопоставления.
- Профили «задача → модель» и сохранённые бюджеты.
- Автоматическое обновление по расписанию (только вручную + предупреждение о возрасте).
- Автоматический перевод описаний скриптом (перевод делает агент по процедуре в SKILL.md).
- Публикация снапшота оценок с данными AA.

## Решения владельца после этапа 0 (2026-10-17)

| № | Вопрос | Решение |
|---|---|---|
| D1 | Конфигурация усилия | Представляет семейство конфигурация **Medium**. Правило для моделей без Medium — см. открытый вопрос Q1 |
| D3 | Не-чат модели | **Исключаются** из рекомендаций, флагманов и spotlight по признаку «в выходных модальностях нет text». В справке и сравнении остаются |
| D4 | Категория agentic | Качество = AA `terminalbench_hard`; резерв (AA недоступен или нет значения) = Arena agent overall |
| D5 | Категория reasoning | Качество = AA Intelligence Index (не Math Index); категория помечается «оценка по общему рейтингу» |

Следствия, которые надо учесть при реализации:
- D5 переводит reasoning в категории «без прямого бенчмарка»: прямых бенчмарков остаётся три (coding, agentic, vision). Нужно поправить конституцию (термин «Прямой бенчмарк») и ТЗ-таблицу §7 — вместе с закрытием Q1 и Q2, одним коммитом.
- D3: признак «не-чат» вычисляется только по `output_modalities`. У 10 записей Anthropic этого блока нет (см. Q2); для них модальности берутся у соседнего варианта семейства.
