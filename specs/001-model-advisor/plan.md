## Approach

Порядок следует этапам ТЗ §8. Этап 0 идёт первым и без производственного кода: одноразовые пробные скрипты в `specs/001-model-advisor/stage0/` делают живые запросы и пишут отчёт `report.md`. По отчёту закрываются четыре `[NEEDS CLARIFICATION]` в `spec.md` и фиксируется таблица категорий.

Дальше по очереди:

1. `fetch_models.py` — каталог, цены в $/1M, семейства с представителем «базовый вариант без суффиксов» и пометкой расхождения цен.
2. `fetch_scores.py` — два адаптера с общим форматом `{value, source, metric, date}`; адаптер AA возвращает либо данные, либо `unavailable` с кодом причины, никогда не исключение наружу; автосопоставление имён с уровнем уверенности.
3. `query.py` — чистые функции расчёта (value, медиана и нормализация по источнику, флагманы, spotlight, плюсы и минусы) отделены от вывода, чтобы тестироваться на фикстурах.
4. `SKILL.md`, `references/maintenance.md`, перевод описаний агентом.
5. Приёмка на живых данных.

Секреты: ключ читается только в одном месте (функция загрузки конфигурации), в остальной код передаётся как значение внутри адаптера AA; тексты ошибок фильтруются от ключа.

## Test strategy

Команда: `python -m unittest discover -s tests -v` (stdlib, без pytest). Тесты работают на малых фикстурах в `tests/fixtures/`, сеть не нужна.

| Критерии | Тест |
|---|---|
| AC-1, AC-2 | фикстура ответа API Nous: нормализация цен, схлопывание, представитель, пометка расхождения цен; порядок поиска токена |
| AC-3, AC-4 | подмена HTTP-слоя: 200 / нет ключа / 401 / 403 / 429 / таймаут / мусорный ответ → статус и причина в снапшоте, остальные источники не ломаются; ключ не встречается в сериализованном снапшоте |
| AC-5, AC-17 | заголовок свежести при разных возрастах и статусах AA; побайтовое равенство двух прогонов |
| AC-6–AC-9 | фикстуры оценок: ранжирование, медианный порог, пометки, budget, смешанные источники |
| AC-10–AC-12 | флагманы с приоритетом AA, разработчик без рейтинга, модель только с Arena, spotlight без дублей и пересечение с флагманами |
| AC-13–AC-16 | compare, show, правила плюсов/минусов, перевод/оригинал по хешу, устаревшие id |
| AC-18, AC-19 | проверка .gitignore, отсутствие сторонних импортов (разбор AST), атрибуция в выводе |

Приёмка на живых данных (этап 5) — ручной прогон `python scripts/query.py …` и отчёт; не заменяет юнит-тесты.
