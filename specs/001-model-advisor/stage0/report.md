## 2. Artificial Analysis (бесплатный тариф)

- Эндпоинт `https://artificialanalysis.ai/api/v2/data/llms/models`, заголовок `x-api-key`. **Один запрос** возвращает всё: 704 записи, 623 КБ. Ключ работает.
- Записи — это конфигурации модели с уровнем усилия: `Claude Opus 5.5 (Max, …)`, `(High, …)`, `(Medium, …)`. 704 записи ≈ 508 моделей.
- Метрики и сколько записей их имеют: Intelligence Index 694, HLE 666, GPQA 617, LCR 577, IFBench 450, tau2 440, TerminalBench Hard 432, MMLU-Pro 349, LiveCodeBench 343, **Math Index 270, Coding Index 258**, SciCode 233, AIME 194–270.
- **Отдельного Agentic Index нет**, как и Multilingual Index. Для агентных задач доступны только отдельные бенчмарки (`tau2`, `terminalbench_*`).
- Поведение при ошибке: без ключа — `401 {"error":"API key is required"}`; мусорный ключ — `401 {"error":"Invalid API key."}`. Ответы 403 и 429 не воспроизведены, заголовков лимита в ответе нет. Суточный лимит бесплатного тарифа проверить не удалось.

## 3. LMArena (датасет `lmarena-ai/leaderboard-dataset`, API Hugging Face datasets-server)

- Доступно 24 конфигурации; нужные: `text` (11033 строк), `vision` (1124), `agent` (52), `webdev` (622), `document` (44). Колонки: `model_name, organization, rating, rating_lower/upper, vote_count, rank, category, leaderboard_publish_date`.
- Категории `text`: `overall, coding, math, creative_writing, instruction_following, longer_query, russian, chinese, hard_prompts, expert, multi_turn` и около 30 других. У `vision`: `overall, ocr, diagram, captioning, …`. У `agent`: только `overall`.
- Даты: `text` 2026-10-15, `agent` 2026-10-16, `vision` в основном 2026-10-09, **но 34 строки от 2026-01-09** — в одной конфигурации смешаны даты, брать надо самую свежую для пары модель×категория.
- **Лимиты Hugging Face — реальная проблема.** Постраничная выгрузка `text` (111 страниц по 100) упёрлась в `429` и прошла только с экспоненциальной паузой (5→40 с), заняла несколько минут. Фильтр по категории (`/filter`) в одной пробе вернул `500: the dataset index is loading` — как он работает в штатном режиме, не проверено. Важно для резервного режима: это единственный источник, и он нестабилен.

## 4. Автосопоставление «каталог Nous ↔ бенчмарк» (331 семейство)

| Метрика | Семейств | Доля |
|---|---|---|
| AA Intelligence Index | 155 | 47% |
| Arena text overall | 117 | 35% |
| AA или Arena | 173 | 52% |
| **Ни того ни другого** | **158** | **48%** |
| из них не-чат (embeddings и т. п.) | ≥ 18 | |

Из 162 семейств, не нашедших пары при простой нормализации: 32 нашлись после более агрессивной очистки, 60 — «нечёткие кандидаты», 70 — аналога нет.

**Нечёткие кандидаты нельзя принимать автоматически.** Примеры: `openai/gpt-6-sol-pro → gpt-6-sol` (разные модели, «pro» не то же, что базовая), `openai/gpt-terra → gpt-5-6-terra` (другая версия), `qwen3.8-omni-flash → qwen3-5-omni-flash`. Принять такие совпадения значит выдать оценку соседней модели, что запрещено критерием приёмки и принципом «нет данных ≠ ноль». Правило для реализации: автосовпадение только по точному равенству после нормализации; нечёткие — в `name_map.json` со статусом `candidate`, не используются в выводе.

## 6. Согласованность двух общих рейтингов

- Пар «AA × Arena» по именам: 171. Корреляция рангов (Спирмен) **0,87**, Пирсон 0,74.
- Шкалы: AA 3,8–57,6, Arena 1023–1532 — напрямую не сравнимы.
- Из 21 разработчика, у которых есть оба рейтинга, у **7 (33%)** флагман различается в зависимости от источника.
- Разработчиков в каталоге 45: с AA — 24, с Arena — 21, **только с Arena — 0**, ни с чем — 21. То есть правило «Arena, если нет AA» для флагманов при живом AA ничего не добавляет; Arena важна только в резервном режиме и для отдельных моделей.
- Вывод: в рамках одной выдачи смешивать шкалы можно лишь ограниченно. Моделей, у которых Arena — единственный рейтинг, всего 173−155 = **18**.

## 7. Выводы для реализации

1. Источники доступны и работают; осуществимость подтверждена.
2. Нужны решения владельца по пяти вопросам — см. «Открытые вопросы» в `spec.md`.
3. `fetch_scores.py` должен: делать один запрос к AA; качать из LMArena только нужные конфигурации и категории; выдерживать 429/500 с паузами и сообщать о неполной загрузке в `scores.json`, а не молча отдавать частичные данные.
4. Схема `models.json` меняется: ключ цены `input_cache_read`; добавляется признак чат/не-чат; у семейства должен быть способ выбора представителя при отсутствии базового варианта.
