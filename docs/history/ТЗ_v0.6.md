# ТЗ — «Советник по моделям Nous» (портативный скилл)

Версия 0.6 · Дата: 2026-10-17 · Статус: этап 0 выполнен (`specs/001-model-advisor/stage0/report.md`), решения владельца приняты

Изменения v0.6 относительно v0.5 (по итогам этапа 0): конфигурация усилия Medium (§4 FR-1); алиасы `~…-latest` не получают оценок; не-чат модели исключены из рекомендаций, флагманов и spotlight; reasoning переведён на оценку по общему рейтингу (Intelligence Index) — прямых бенчмарков три: coding, agentic, vision; agentic = AA `terminalbench_hard`, резерв Arena agent. Затронуты: §2, FR-1, FR-3, FR-6, §7, §10.

Изменения v0.5 относительно v0.4: общий рейтинг — два источника (AA Intelligence Index, а при его отсутствии у модели — Arena overall); при недоступности API Artificial Analysis скилл целиком переходит на открытый источник LMArena (резервный режим). Затронуты: §2, FR-2, FR-3, FR-6, FR-7, §6, §7, §8, §9, §10, §11.

---

## 1. Цель и назначение

Помочь пользователю подписки Nous Portal быстро отвечать на вопросы:

- «Какие модели сейчас актуальны и сколько они стоят?»
- «Каковы характеристики модели X, её сильные и слабые стороны?»
- «Какая модель лучше всего подойдёт под мою задачу по соотношению цена/качество?»
- «Сравни X и Y — что выбрать?»

Инструмент — **портативный скилл**: набор файлов, который запускается независимо от агента (Hermes, Claude Code, обычный Python).

**Принцип данных (решение пользователя):** никакой ручной курации. Каталог и цены берутся из API Nous, оценки качества — из независимых бенчмарков (Artificial Analysis, LMArena), у каждой цифры указан источник и дата. Если данных нет — инструмент говорит «нет данных», а не придумывает оценку.

## 2. Термины

| Термин | Значение |
|---|---|
| **Каталог** | Список моделей Nous Portal (≈426 записей) с метаданными и ценами |
| **Снапшот каталога** | `data/models.json`, создаётся `fetch_models.py` |
| **Снапшот оценок** | `data/scores.json`, создаётся `fetch_scores.py` из внешних бенчмарков |
| **Семейство модели** | Каталожные записи-дубли (`~…-latest`, `:US`, `(batch)`, датированные ревизии) схлопываются в одну модель |
| **Spotlight** | Автоматический список свежих и примечательных моделей для обзора рынка |
| **Флагманы** | Автоматический список лучшей модели каждого разработчика по общему рейтингу |
| **Оценка по общему рейтингу** | Для категорий без прямого бенчмарка качество берётся из общего рейтинга модели; в выводе всегда помечено «оценка по общему рейтингу» |
| **Категория задачи** | Тип работы: кодинг, бизнес-ТЗ и т.д. (11 штук, §7) |
| **Прямой бенчмарк** | Метрика, которая напрямую измеряет категорию (coding, agentic, vision) |
| **Общий рейтинг** | Обобщённая метрика модели, показывается в любой категории: AA Intelligence Index, а если его у модели нет — Arena overall. У каждого значения указан источник; шкалы источников несопоставимы напрямую (§7) |
| **Резервный режим** | Состояние, когда API Artificial Analysis недоступен (нет ключа, ошибка доступа, лимит, нет сети): все оценки берутся из LMArena, причина указывается в заголовке вывода (FR-2, FR-7) |

## 3. Пользовательские сценарии

1. **Обзор рынка.** Два режима выборки: **spotlight** («покажи свежие и необычные модели»: свежие релизы и примечательные по цене, **не только флагманы, но и нишевые**) и **флагманы** («покажи флагманские модели»: лучшая модель каждого разработчика). Для каждой — цена, контекст, модальности, переведённое описание из каталога.
2. **Справка по модели.** «Что за модель DeepSeek V4 Pro?» → карточка: переведённое описание, цена, контекст, модальности, оценки бенчмарков с источниками, плюсы и минусы, выведенные из цифр.
3. **Подбор под задачу.** «Нужно писать код» → топ-N по лучшему соотношению цена/качество (бюджет пользователь не задаёт). Для категорий без прямого бенчмарка (например, бизнес-ТЗ) инструмент считает рекомендацию по общему рейтингу модели и прямо помечает: «нет прямого бенчмарка, оценка по общему рейтингу».
4. **Сравнение.** «Сравни Claude Sonnet 5.5 и DeepSeek V4 Pro» → таблица: цена, контекст, модальности, оценки по категориям (где есть данные), общий рейтинг.
5. **Обновление.** «Обнови данные» → пересоздание снапшота каталога и снапшота оценок.

## 4. Функциональные требования

### FR-1. Каталог и цены
- `fetch_models.py` тянет `https://inference-api.nousresearch.com/v1/models` (Bearer-токен).
- Цены нормализуются в **$/1M токенов** (API отдаёт цену за 1 токен, умножать на 1e6).
- Сохраняет `data/models.json` со схемой §6; фиксирует `fetched_at`; идемпотентен.
- Схлопывает дубли в семейства (правила: префикс `~`, суффиксы `:US`, `:batch`, `:free`, `-latest`, датированные суффиксы). Исходные id сохраняются внутри семейства.
- **Представитель семейства** — базовый вариант без суффиксов. Алиас `~…-latest` без базового варианта (в каталоге 20 штук; целевую версию определить нельзя: `canonical_slug` указывает на сам алиас) остаётся отдельным семейством, представитель — сам алиас; оценок он не получает, в выводе помечается «алиас: версия не определена», в рекомендации и флагманы не попадает. Если у семейства есть только вариант `:free` — представителем становится он.
- Модальности берутся у представителя; если блок `architecture` у него пуст (10 записей Anthropic), — у ближайшего варианта того же семейства.
- **Признак «не-чат»:** в `output_modalities` нет `text` (34 записи embeddings; плюс записи с генерацией изображений). Такие семейства исключаются из рекомендаций, флагманов и spotlight; в справке и сравнении остаются.
- **Конфигурация усилия.** AA и Arena хранят модель в нескольких конфигурациях (Max, High, Medium…). Семейство представляет **Medium**; если её нет — порядок предпочтения `medium → high → low → xhigh → max → minimal → non-reasoning`; единственная конфигурация берётся как есть. Если выбрана не Medium, в строке пометка «конфигурация: High». Порядок задаётся в `config.json`.

### FR-2. Оценки качества из бенчмарков
- `fetch_scores.py` собирает оценки из двух источников:
  1. **Artificial Analysis** (REST API, ключ в переменной `AA_API_KEY`): индексы Intelligence, Coding, Agentic, Math и др., скорость, цена. Основной источник. Без ключа или при ошибке подключения включается резервный режим (ниже).
  2. **LMArena** (открытый датасет `lmarena-ai/leaderboard-dataset` на Hugging Face, CC-BY-4.0): рейтинги по текстовым категориям, vision и агентам. Загрузка через JSON-API Hugging Face (datasets-server), без pandas и parquet.
- **Резервный режим (AA недоступен).** Срабатывает при: отсутствии ключа, ответе 401/403 (ключ недействителен), 429 (лимит), таймауте или сетевой ошибке, нераспознаваемом ответе. Поведение:
  - `fetch_scores.py` не завершается ошибкой, а продолжает работу только с LMArena; в `scores.json` источник AA получает `status: "unavailable"` и `reason` (код причины без секретов);
  - для каждой метрики, у которой есть аналог в LMArena (общий рейтинг, coding, reasoning, agentic, vision), значение берётся оттуда с пометкой источника;
  - без данных остаются только метрики, у которых нет аналога в LMArena (скорость, цена AA и т.п.) — «нет данных»;
  - значения AA из предыдущего снапшота не переносятся: снапшот описывает один момент времени.
- **Выбор источника для каждой модели** (когда AA доступен, но покрывает не все модели): для метрики берётся значение AA; если его у модели нет (нет в AA или нет уверенного сопоставления) — аналог из LMArena. Источник указывается в каждом значении и в каждой строке вывода.
- Сопоставление имён «каталог Nous ↔ бенчмарк» — **автоматическое** (нормализация имён, сравнение по семейству). Совпадение сохраняется в `data/name_map.json` вместе с уровнем уверенности. Нет уверенного совпадения → у модели «нет данных».
- Каждое значение хранится как `{value, source, metric, date}`. Никаких ручных правок оценок.

### FR-3. Подбор под задачу (цена/качество)
- Для категорий с прямым бенчмарком (coding, agentic, vision) качество берётся из соответствующей метрики AA; если её у модели нет или AA недоступен — из аналогичной категории LMArena (таблица §7). Источник показывается в каждой строке.
- Для остальных категорий качество берётся из **общего рейтинга** модели (AA Intelligence Index, а если его у модели нет — Arena overall; в резервном режиме — всегда Arena overall). Весь вывод таких категорий помечается «оценка по общему рейтингу, не специфична для категории», в таблице колонка называется «Общий рейтинг», а не «Качество».
- Бюджет не задаётся; оптимизируется value = качество / смешанная_цена (формула §7). Если в одной выдаче смешаны источники (AA и Arena), нормализация идёт по каждому источнику отдельно (§7), а в каждой строке показан источник; такая выдача сопровождается пометкой «источники смешаны».
- Чтобы дешёвые слабые модели не выигрывали, в ранжирование попадают только модели из верхней половины по качеству в категории (порог в `config.json`).
- Ранжирование в категориях без прямого бенчмарка отличается от остальных только источником качества и пометкой; формула и пороги те же. Единственное исключение: **budget** ранжируется по цене среди моделей выше порога общего рейтинга.

### FR-4. Сравнение моделей
- Принимает 2+ идентификаторов или алиасов, выдаёт таблицу: цена (in/out), контекст, модальности, оценки по категориям с источниками, общий рейтинг.
- Где данных нет, ячейка содержит «нет данных», не пустое место и не ноль.

### FR-5. Описания, плюсы и минусы
- **Описание:** текст из каталога Nous, переведённый на русский. Перевод делает агент при обновлении данных (скрипту на stdlib нечем переводить). Результат хранится в `data/descriptions_ru.json` вместе с хешем оригинала и пометкой «машинный перевод» и датой. Скрипт `query.py` показывает оригинал, если перевода нет или оригинал изменился.
- **Плюсы/минусы:** выводятся детерминированными правилами из цифр, без свободного текста. Примеры правил: «нет vision» (нет image во входных модальностях), «дорогой output» (цена output выше порога), «контекст ≥ 1M», «в топе по Coding Index», «ниже медианы по скорости». Пороги задаются в `config.json`.
- Перевод ограничивается моделями, у которых есть оценки или которые попали в spotlight (ориентир 40–60 моделей); остальные показываются с оригинальным описанием.

### FR-6. Выборки моделей для обзора рынка
Команда `query.py models --set <spotlight|flagships>`; без параметра показывает оба списка.

**Выборка `spotlight`** (свежие и примечательные)
- Формируется автоматически, без курации, по свежести релиза (`created`) и цене.
- Правило-черновик: семейства моделей, созданные за последние N дней (по умолчанию 45), по убыванию свежести; плюс блок «необычно дёшево для своего уровня» (низкая цена при наличии оценок выше медианы).
- Дубли схлопнуты (FR-1), чтобы одна модель не занимала весь список.
- В выводе spotlight нет субъективных «почему примечательна»: только факты (дата релиза, цена, контекст, модальности, переведённое описание).

**Выборка `flagships`** (флагманские)
- Для каждого разработчика (префикс id до `/`) выбирается одно семейство с максимальным общим рейтингом. Шкалы AA и Arena несопоставимы, поэтому сравнение идёт внутри одного источника с приоритетом AA: если у разработчика есть хотя бы одно семейство с AA Intelligence Index, флагман выбирается среди них по AA; только если AA нет ни у одного семейства — по Arena overall. Разработчики без рейтинга ни из одного источника в список не попадают и перечисляются отдельной строкой «нет данных для определения флагмана».
- Список сортируется так: сначала флагманы с рейтингом AA (по убыванию), затем флагманы с рейтингом Arena (по убыванию); источник указан в каждой строке. В резервном режиме весь список — по Arena. Показываются рейтинг с источником, цена, value, контекст, модальности, переведённое описание.
- Критерий флагмана задаётся одним правилом в `config.json` и показывается в заголовке вывода («флагман = модель разработчика с максимальным общим рейтингом; AA имеет приоритет над Arena»).
- Модели из spotlight, которые одновременно флагманы, помечаются в обоих списках.

### FR-7. Свежесть данных
- **Каждый вывод** начинается с заголовка: дата снапшота каталога и дата снапшота оценок, плюс возраст («создан 3 дня назад»).
- Старше порога (по умолчанию 7 дней) → подсказка с командами обновления: `fetch_models.py` и `fetch_scores.py`.
- Если AA недоступен, заголовок сообщает причину и режим: «AA: нет данных (не задан AA_API_KEY / ошибка доступа / превышен лимит / нет сети); оценки — из LMArena». Строка берётся из `scores.json`, а не угадывается при выводе.

### FR-8. Целостность данных
- При запуске проверяется: id из `name_map.json` и `descriptions_ru.json`, которых нет в актуальном каталоге, помечаются как устаревшие (не удаляются молча).

## 5. Нефункциональные требования

### NFR-1. Портативность
- Самодостаточная директория: `SKILL.md` + `scripts/` + `data/`.
- Скрипты на **чистом Python 3.10+ (stdlib only)**: `urllib`, `json`, `argparse`, `pathlib`. Без `requests`, `pandas`, пакета hermes.
- Запуск `python3 scripts/query.py …` одинаков из любого агента и вручную.
- **Токен Nous** по приоритету: аргумент `--token` → переменная `NOUS_API_TOKEN` → поиск в `auth.json` (`~/.hermes/auth.json`, `$HERMES_HOME/auth.json`, `%LOCALAPPDATA%\hermes\auth.json`).
- **Ключ AA** по приоритету: переменная окружения `AA_API_KEY` → файл `.env` в корне скилла (строка `AA_API_KEY=...`). Файл `.env` внесён в `.gitignore` и не распространяется. Ключ никогда не печатается в выводе и логах.
- **Offline-режим:** без сети `query.py` работает на локальных снапшотах.

### NFR-2. Лицензии и данные
- Artificial Analysis (бесплатный тариф): «internal use only, no redistribution». Поэтому `data/scores.json` с данными AA **не публикуется и не входит в дистрибутив скилла**; у каждого пользователя он создаётся локально своим ключом.
- LMArena: CC-BY-4.0, нужна атрибуция (указывается в выводе).
- Лимит бесплатного AA API (100–1000 запросов в сутки, документация противоречива) учитывается: `fetch_scores.py` делает минимум запросов (список моделей одним вызовом).

### NFR-3. Расширяемость
- Новая категория = строка в `config.json` + привязка к метрике бенчмарка.
- Новый источник бенчмарков = новый адаптер в `fetch_scores.py` с тем же форматом `{value, source, metric, date}`.

### NFR-4. Воспроизводимость и честность
- Одинаковые снапшоты → одинаковый вывод. Все цены, value и правила плюсов/минусов считаются в коде.
- Нигде не показываются оценки, придуманные моделью или человеком. Нет данных → «нет данных».

## 6. Архитектура и структура скилла

```
hermes-model-advisor/
├── SKILL.md                    # триггеры, команды, процедура обновления (включая перевод описаний агентом)
├── config.json                 # пороги: возраст снапшота, spotlight, правила плюсов/минусов, привязка категорий к метрикам
├── scripts/
│   ├── fetch_models.py         # FR-1: каталог Nous → data/models.json
│   ├── fetch_scores.py         # FR-2: AA + LMArena → data/scores.json, data/name_map.json
│   └── query.py                # FR-3..8: spotlight / show / recommend / compare / search
├── data/
│   ├── models.json             # снапшот каталога (генерируется)
│   ├── scores.json             # снапшот оценок (генерируется, не распространяется — NFR-2)
│   ├── name_map.json           # автосопоставление каталог ↔ бенчмарки + уверенность
│   └── descriptions_ru.json    # переводы описаний (создаёт агент при обновлении)
└── references/
    └── maintenance.md          # процедура обновления, перевод, диагностика сопоставления
```

## 7. Модель «цена/качество»

### Категории (11, без изменений)

| Категория | Покрывает | in:out | Источник качества |
|---|---|---|---|
| coding | Программирование, отладка | 3:1 | **да** (AA Coding Index; резерв — Arena coding) |
| reasoning | Математика, логика | 2:1 | нет прямого → **оценка по общему рейтингу** (решение владельца: Math Index есть лишь у 15% семейств) |
| agentic | Агентные задачи, инструменты | 5:1 | **да** (AA `terminalbench_hard`; резерв — Arena agent overall) |
| vision | Мультимодальные задачи | 4:1 | **да** (Arena vision — единственный источник), только для моделей с image-входом |
| business_spec | Бизнес-ТЗ, бизнес-документы | 2:1 | нет прямого → **оценка по общему рейтингу** |
| tech_spec | Техническое ТЗ, спецификации | 3:1 | нет прямого → **оценка по общему рейтингу** |
| writing | Письмо, редактура | 1:1 | нет прямого → **оценка по общему рейтингу** |
| translation | Перевод | 1:1 | нет прямого → **оценка по общему рейтингу** |
| data_analysis | Длинные документы, извлечение | 6:1 | нет прямого → **оценка по общему рейтингу** |
| creative | Креатив, идеи | 1:2 | нет прямого → **оценка по общему рейтингу** |
| budget | Массовые дешёвые задачи | 5:1 | общий рейтинг (AA, при отсутствии — Arena overall) как порог; ранжирование по цене среди моделей выше порога |

**Важно:** таблица прямых бенчмарков — гипотеза на момент ТЗ. Этап 0 (§8) проверяет, какие метрики реально отдаёт бесплатный тариф AA и какие категории есть в датасете LMArena. Столбец «резерв» — тоже гипотеза: этап 0 проверяет, какие категории LMArena реально соответствуют метрикам AA; если аналога нет, в резервном режиме категория остаётся без качества («нет данных») либо переходит на оценку по общему рейтингу LMArena. Если найдётся прямая метрика (например, AA Multilingual Index для translation или AA-LCR для data_analysis), категория переходит на неё; если прямой метрики нет в бесплатном тарифе, категория остаётся на оценке по общему рейтингу.

### Формулы
```
смешанная_цена(категория) = prompt × ratio_in + completion × ratio_out
качество_норм(категория)  = min-max нормализация метрики среди моделей с данными (0–100), отдельно по каждому источнику (AA и Arena не смешиваются в одной шкале)
value = качество_норм / смешанная_цена
```
В ранжирование попадают модели выше медианы качества в категории (порог в `config.json`); медиана считается внутри источника. Нормализованные значения разных источников сравниваются между собой только в пределах одной выдачи и с явной пометкой «источники смешаны»; в резервном режиме источник один, и вопрос не возникает. Значения и источники показываются рядом с value, чтобы пользователь видел исходные цифры, а не только производную.

## 9. Критерии приёмки

- [ ] `fetch_models.py`: 400+ записей, цены в $/1M, дубли схлопнуты в семейства.
- [ ] `fetch_scores.py`: источник с ошибкой (нет ключа, нет сети) не ломает остальные; статус каждого источника записан в `scores.json`.
- [ ] Сопоставление: у модели нет уверенного совпадения → «нет данных», а не оценка соседней модели.
- [ ] `query.py recommend --task coding` → топ-N с value, исходными цифрами и источниками.
- [ ] `query.py recommend --task business_spec` → рекомендация по общему рейтингу, каждая строка и заголовок помечены «оценка по общему рейтингу».
- [ ] `query.py models --set flagships` → по одной модели на разработчика с максимальным общим рейтингом (AA приоритетнее Arena); источник указан в каждой строке; разработчики без рейтинга перечислены отдельно.
- [ ] Модель без AA, но с Arena overall, показывается с общим рейтингом Arena и пометкой источника, а не «нет данных».
- [ ] Ключ AA читается из переменной `AA_API_KEY` или из `.env`; в выводе и логах он не появляется ни в каком виде.
- [ ] `query.py compare A B` → таблица; недостающие значения показаны как «нет данных».
- [ ] `query.py spotlight` → свежие семейства без дублей; только фактические поля.
- [ ] Каждый вывод начинается с дат обоих снапшотов и возраста; старше 7 дней → подсказка обновить.
- [ ] Без `AA_API_KEY`, с недействительным ключом (401/403), при 429 и при отсутствии сети `fetch_scores.py` завершается успешно на данных LMArena; в `scores.json` у AA `status: unavailable` и причина; заголовок вывода сообщает причину и что оценки — из LMArena.
- [ ] В резервном режиме работают `recommend`, `compare` и `models --set flagships` на данных LMArena; метрики без аналога показаны как «нет данных».
- [ ] Ключ AA не появляется ни в `scores.json`, ни в тексте причины ошибки.
- [ ] Плюсы/минусы воспроизводимы: правила в `config.json`, тот же вход даёт тот же вывод.
- [ ] Описание на русском помечено «машинный перевод» и датой; при изменении оригинала показывается оригинал.
- [ ] Работает с чистым Python 3.10+ без установки пакетов.
- [ ] В вывод включена атрибуция LMArena (CC-BY-4.0).

## 10. Принятые решения

| № | Вопрос | Решение |

| 2 | Покрытие | Ориентир 40–60 моделей с переведёнными описаниями; метрики — для всех сопоставленных моделей |
| 3 | Язык | Русский |
| 4 | Категории | 11 штук, без изменений |
| 5 | Профили «задача → модель» | Нет, только разовые запросы |
| 6 | Обновление | Вручную по запросу + предупреждение о возрасте в заголовке |
| 7 | Spotlight | Автоматически по свежести и цене, без курации |
| 8 | Плюсы/минусы | Гибрид: только правила от цифр + переведённое описание из каталога Nous |
| 9 | Категории без прямых бенчмарков | Рекомендация по общему рейтингу с обязательной пометкой «оценка по общему рейтингу» (изменено в v0.4) |
| 10 | Ключ AA | Пользователь создаёт сам; хранится в `.env` в папке скилла или в переменной `AA_API_KEY`; без ключа или при недоступности API AA используется только LMArena (резервный режим) |
| 11 | Выборки для обзора рынка | Две: `spotlight` (свежие и примечательные) и `flagships` (лучшая модель каждого разработчика по общему рейтингу) |
| 12 | Общий рейтинг | Два источника: AA Intelligence Index, а если его у модели нет — Arena overall; источник всегда показывается. Заменяет решение «только AA» из конституции (владелец, 2026-10-17) |
| 14 | Конфигурация усилия | Medium; если нет — порядок `medium → high → low → xhigh → max → minimal → non-reasoning`; нестандартный выбор помечается в строке |
| 15 | Алиасы `~…-latest` | Остаются отдельными семействами без оценок, помечаются «версия не определена»; версия по догадке не подставляется |

| 17 | Метрики категорий | reasoning — оценка по общему рейтингу (Intelligence Index); agentic — AA `terminalbench_hard`, резерв Arena agent overall |
| 13 | Недоступность API AA | Резервный режим: все оценки из открытого LMArena, причина в заголовке; без ошибки и без ручных действий |

## 11. Остаётся подтвердить

1. **Ключ AA.** Получен пользователем; нужно вписать его в `.env` (см. NFR-1). Без ключа (или при недоступности API) coding и agentic опираются только на LMArena, данных будет заметно меньше.
2. **Spotlight без курации** сильнее зависит от качества правил: возможны модели, свежие по дате, но малоинтересные. Порог свежести (45 дней) и фильтры подстраиваются после первого прогона.
3. **Определение флагмана** по максимальному общему рейтингу не учитывает цену и назначение: у разработчика флагманом может оказаться очень дорогая модель. Критерий вынесен в `config.json` и показывается в заголовке вывода.
4. **Несопоставимость шкал.** AA Intelligence Index и Arena overall (Elo-подобный рейтинг) измеряют разное. Принятые меры: нормализация и медиана по источнику, приоритет AA при выборе флагмана, пометка источника в каждой строке. Остаётся риск: в смешанной выдаче модель с Arena-рейтингом может выглядеть лучше или хуже, чем была бы по AA. Этап 0 оценивает согласованность шкал на моделях, у которых есть оба рейтинга; по результату правило смешивания уточняется в spec.md.
