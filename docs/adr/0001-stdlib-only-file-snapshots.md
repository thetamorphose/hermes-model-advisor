# ADR-0001: Stdlib-only, JSON-снапшоты как контракт, раскладка репозитория

## Status
proposed

## Context
ТЗ v0.6 (NFR-1) требует портативности: скилл запускается одинаково из Hermes, Claude Code и вручную, без установки пакетов. Скрипты `fetch_*` и `query.py` обмениваются данными только через файлы `data/*.json`. Один и тот же репозиторий содержит и сам скилл, и governance-файлы проекта (`tools/`, `docs/`, `specs/`, `tasks/`, `logs/`).

Что показал этап 0 (`specs/001-model-advisor/stage0/report.md`):
- API Nous, AA и датасет LMArena читаются обычным HTTP + JSON; stdlib достаточно.
- Реальные ответы расходятся со схемой ТЗ §6 (ключ цены `input_cache_read`, пустой блок `architecture` у 10 записей, `status/reason` у источника AA), то есть схема снапшотов ещё изменится.
- Постраничная выгрузка LMArena через Hugging Face упирается в 429.

## Options considered
Решение состоит из трёх частей.

**A. Зависимости**
1. Чистый Python 3.10+, только stdlib (по ТЗ).
2. Зависимости (`requests`, `pandas`, `pyarrow`): удобнее парсить parquet и считать статистику, но ломает «запуск без установки».

**B. Формат обмена между скриптами**
1. JSON-файлы в `data/` с полем `schema_version` (по ТЗ).
2. SQLite (stdlib, но не читается глазами и плохо диффится в Git).

**C. Раскладка репозитория**
1. Корень репозитория = скилл: `SKILL.md`, `config.json`, `scripts/`, `data/` лежат рядом с `docs/`, `specs/`, `tasks/`, `tools/`, `logs/` (так нарисовано в ТЗ §6).
2. Скилл в подпапке `skill/`: отдельная самодостаточная директория, которую можно копировать целиком; governance-файлы остаются в корне.

## Decision
Предложено (статус остаётся `proposed` до ответа владельца): **A1, B1 и C2**.
- A1 и B1 формализуют уже утверждённое ТЗ.
- C2 отличается от ТЗ §6. Причина: при C1 копирование «папки скилла» в профиль агента увлекает `tools/`, `logs/` (экспорт сессий), `specs/` и историю ТЗ; NFR-1 требует самодостаточной директории `SKILL.md + scripts + data`, а NFR-2 запрещает распространять `data/scores.json`. При C2 граница дистрибутива очевидна. `.env` и `data/scores.json` остаются в `.gitignore`, путь к ним в `.gitignore` меняется на `skill/…`.

## Consequences
### Positive
- Нулевая установка, одинаковый запуск везде.
- Снапшоты читаются и диффятся; их легко подменять фикстурами в тестах.
- (C2) Дистрибутив скилла отделён от рабочих материалов проекта.

### Negative
- LMArena читается через JSON-API Hugging Face без parquet: полнота и скорость зависят от его лимитов (на этапе 0 получены 429 и один 500). Требуются паузы и явная отметка неполной загрузки в `scores.json`.
- Нет pandas: медиана и min-max пишутся вручную и покрываются тестами.
- Схема снапшотов — публичный контракт между скриптами: изменение требует повышения `schema_version`.
- (C2) Отклонение от структуры ТЗ §6: нужна правка схемы раскладки в ТЗ и пути в `plan.md`.
