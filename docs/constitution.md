# Project Constitution

## Domain vision

_Утверждено владельцем 2026-10-17._

Подписчику Nous Portal трудно быстро ответить на три вопроса: какие модели сейчас доступны, сколько они стоят и какая из них лучше подойдёт под его задачу. Продукт — советник, который отвечает на эти вопросы честно и проверяемо.

Что делает его ценным:

1. **Данные без домыслов.** Список моделей и цены берутся из самого сервиса подписки, оценки качества — только из независимых бенчмарков. У каждой цифры указаны источник и дата; нет данных — советник так и говорит, а не придумывает оценку.
2. **Выбор по задаче, а не по бюджету.** Пользователь называет задачу, а не сумму. Советник ранжирует модели по соотношению цена/качество и не пускает в рекомендации дешёвые, но слабые.
3. **Прозрачные допущения.** Если для задачи нет прямого бенчмарка, оценка строится по общему рейтингу, и это сказано прямо. Каждый ответ начинается с даты данных и предупреждает, что они устарели.
4. **Обзор рынка шире флагманов.** Рядом с лучшими моделями разработчиков показываются свежие и необычные — только факты, без субъективных пояснений.
5. **Воспроизводимость.** Одни и те же данные дают один и тот же ответ; плюсы и минусы модели выводятся из цифр, а не из мнения.

Язык общения с пользователем — русский.

## Ubiquitous language

| Term | Meaning | Disallowed synonyms |
|---|---|---|
| Каталог | Список всех моделей Nous Portal с метаданными и ценами. Источник — только сервис подписки. | список моделей, база моделей, прайс-лист |
| Снапшот каталога | Локальная копия каталога с отметкой времени получения. Не содержит оценок. | снапшот (без уточнения), кэш, дамп |
| Снапшот оценок | Локальная копия оценок из внешних бенчмарков (Artificial Analysis, а при его недоступности — открытый LMArena) с отметкой времени сборки; отдельна от снапшота каталога и обновляется отдельно. | снапшот (без уточнения), лидерборд, рейтинговая таблица |
| Семейство модели | Группа записей каталога, которые являются дублями одной модели (алиасы, региональные и пакетные варианты, датированные ревизии), схлопнутая в одну единицу; во всех выводах «модель» = семейство. Представитель семейства — базовый вариант без суффиксов (`~`, `:US`, batch, даты); цену, контекст и описание берём у него, а если у других вариантов цена отличается, это показывается отдельной пометкой. Плавающий алиас `~…-latest` без базового варианта — отдельное семейство без оценок, помечается «версия не определена». | вариант, версия, дубль, линейка |
| Категория задачи | Один из 11 зафиксированных типов работы (кодинг, бизнес-ТЗ и т.д.), для каждого заданы типовое соотношение входа и выхода и источник качества. | тип задачи, профиль, сценарий, тема |
| Оценка | Одно значение из внешнего бенчмарка вместе с источником, метрикой и датой. Ручных и придуманных оценок нет; если значения нет — «нет данных», а не ноль. | балл, скор, мнение, экспертная оценка |
| Прямой бенчмарк | Метрика, которая напрямую измеряет категорию задачи (сейчас: coding, agentic, vision; проверено этапом 0 и решением владельца — reasoning оценивается по общему рейтингу). | профильная метрика, специальный бенчмарк, релевантный рейтинг |
| Качество | Оценка модели по прямому бенчмарку её категории; слово применяется только к таким категориям. Для остальных категорий вместо него — «общий рейтинг». | рейтинг, скор, оценка качества |
| Общий рейтинг | Обобщённая метрика модели, не привязанная к категории: Intelligence Index Artificial Analysis, а если его у модели нет — Arena overall (два источника, решение владельца от 2026-10-17, заменяет прежнее «только AA»). Источник указывается у каждого значения; шкалы источников не сопоставимы напрямую, поэтому нормализация и сравнение идут внутри источника, а смешанная выдача помечается. Если API Artificial Analysis недоступен, общий рейтинг целиком берётся из Arena overall (резервный режим). | качество, общий балл, интеллект модели |
| Оценка по общему рейтингу | Подстановка общего рейтинга (с указанием источника) вместо качества в категории без прямого бенчмарка; такой вывод обязательно несёт эту пометку, а колонка называется «Общий рейтинг», не «Качество». | приблизительная оценка, оценка качества, рейтинг по категории |
| Value | Соотношение цена/качество — нормированное внутри источника качество (в категориях без прямого бенчмарка — нормированный общий рейтинг), делённое на смешанную цену категории; считается только внутри одной категории. В категории budget не применяется: там ранжирование по цене. | выгодность, ценность, value-оценка, рентабельность |
| Флагман | Семейство с максимальным общим рейтингом среди семейств одного разработчика (источник AA приоритетнее Arena, сравнение внутри источника); цена и назначение при выборе не учитываются (решение владельца), поэтому в любом выводе флагманов рядом всегда показываются цена и value. | лучшая модель (без уточнения), топ-модель, главная модель |
| Spotlight | Автоматическая выборка свежих семейств (по дате релиза) и необычно дешёвых для своего уровня; без курации и без субъективных пояснений; не равна выборке флагманов. Числовые пороги — параметры, а не язык: они задаются в конфигурации и настраиваются после первого прогона. | актуальные, нашумевшие, популярные, подборка, курируемый список |
| Конфигурация | Уровень усилия модели в бенчмарке (Medium, High, Max…). Семейство представляет Medium, при его отсутствии — по заданному порядку предпочтения; если взята не Medium, в выводе есть пометка. | режим, уровень |
| Свежесть данных | Возраст снапшота каталога и снапшота оценок, показываемый в заголовке каждого вывода; при превышении порога выводится подсказка обновить. Не путать со свежестью релиза модели. | актуальность данных, возраст кэша |

## Architecture principles

1. Documentation in this repository is the source of truth.
2. One fact has one canonical home.
3. Structural code changes update relevant architecture documentation in the same commit.
4. Missing domain terminology blocks implementation until clarified by the owner.

## Maintenance rules (memory bank)

This constitution is the project's memory bank — durable context read by every agent session.

1. Updating it is part of every task's Definition of Done: if a task changed the language, vision or principles, the constitution changes in the same commit.
2. If this file grows past ~3000 words, split it: stable architecture detail moves to `docs/architecture/system.md`, current project state to `docs/progress.md`; this file keeps only vision, language and principles.
3. Per-feature specifications live under `specs/` and are spec-first: they describe a change while it is implemented. They never replace this file, ADR, architecture docs, code or tests as the durable record.
