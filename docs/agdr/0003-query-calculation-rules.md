# Правила расчётов query.py (recommend, models)

## Context
ТЗ v0.6 §7 и FR-3/FR-6 задают формулы, но оставляют несколько мест, где нужно выбрать правило: что значит «выше медианы» при равных значениях, по какому соотношению in:out считать value флагмана и spotlight (у них нет категории), что делать с моделью без цены или с нулевой ценой, как строить блок «необычно дёшево».

## Options considered
| Вопрос | Варианты |
|---|---|
| Порог качества | (1) строго выше перцентиля (50 = медиана), при единственном значении или равных значениях источника проходят все; (2) не ниже медианы |
| Value флагмана и spotlight | (1) нейтральное соотношение 1:1 из `config.json` (`models_value`), пул нормализации — все семейства с общим рейтингом; (2) соотношение категории reasoning (2:1); (3) value не показывать (нарушает AC-10) |
| Цена 0 и цена не указана | (1) цена 0 → value «бесплатно», сортируется первым; нет цены → «нет данных», в ранжирование не входит, но считается в итоговой строке; (2) считать нулевой цену, которой нет |
| «Необычно дёшево для своего уровня» | (1) семейства выше порога общего рейтинга своего источника, цена (вход 1 + выход 1) в нижних 25% среди них; (2) отношение value к медиане value |
| Флагман без цены | (1) остаётся флагманом, value «нет данных»; (2) пропускается |

## Decision
- Порог: вариант 1. Доля перцентиля (`quality_percentile`) и пороги spotlight — в `config.json`; числа spotlight остаются черновыми до шага 7.
- Value флагманов и spotlight: вариант 1, принято владельцем (см. «Решения владельца»). Соотношение 1:1 выводится в заголовке раздела.
- Цены: вариант 1.
- Блок «необычно дёшево»: вариант 1. Цена сравнивается внутри всей выборки выше порога без разбиения по источникам; качество порогом по источнику.
- Флагман выбирается по общему рейтингу без учёта цены (решение владельца), поэтому флагман без цены допустим.
- Сортировка при равенстве всегда по `family_id`, чтобы вывод был побайтно одинаков (AC-17).
- Возраст снапшотов в заголовке — единственное, что зависит от текущего времени; `--now` фиксирует его для проверок.
- Причина недоступности источника печатается по таблице `unavailable_reasons` из `config.json`; неизвестный код выводится как «причина не указана», сырой текст в вывод не попадает.

## Consequences
- Семейства с одной метрикой на всём источнике не отсекаются порогом.
- Флагманы и spotlight сравнимы по value между собой, но не с value рекомендаций категории.
- Пересмотр 1:1 или определения «необычно дёшево» — правка конфигурации и функции `spotlight`, не схемы данных.

## Решения владельца
1. Value флагманов и spotlight — нейтральное 1:1 из `models_value`: принято владельцем (сессия 3). Определение термина «Value» в конституции уточнено в том же коммите: вне категории value считается по 1:1, указано в заголовке раздела и сравнимо только внутри раздела.
