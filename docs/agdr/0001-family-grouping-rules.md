# Правила схлопывания записей каталога в семейства

## Context
Конституция и ТЗ требуют схлопывать дубли каталога в семейства, но не определяют границы для датированных ревизий и алиасов. Данные каталога (426 записей, проверено на этапе 0):
- 33 записи с датой в id. Часть имеет базу без даты в каталоге (`deepseek-v4-pro-0813` и `deepseek-v4-pro`, `gpt-4o-2024-08-06` и `gpt-4o`), часть — нет (`mistral-small-2603`, `ministral-8b-2512`).
- У датированных вариантов цена с базой совпадает не всегда.
- 20 записей `~…-latest` / `…-latest`. У 19 из них `canonical_slug` и `aliases` указывают на сами эти записи, версию определить нельзя. У `openai/gpt-chat-latest` `canonical_slug` датирован (`…-latest-20260505`): это обычная модель, у которой «latest» — часть имени.

## Options considered
| Option | Pros | Cons |
|---|---|---|
| Срезать дату всегда | Меньше семейств | Придумывает базу, которой нет; подмешивает разные версии (`mistral-large-2407` и `mistral-large`) |
| Срезать дату, только если база без даты есть в каталоге | Не создаёт несуществующих моделей | Часть датированных остаётся отдельными семействами |
| Не срезать даты вообще | Максимально безопасно | Не выполняет требование ТЗ про датированные ревизии |

## Decision
Вариант 2. Дата срезается, только если запись без даты (после снятия `~` и `:суффикса`) есть в каталоге. Остальные датированные записи — отдельные семейства со своим id.
Плавающим алиасом считается запись, у которой `canonical_slug` равен её собственному id и id оканчивается на `-latest` (или начинается с `~`). Только такая запись получает `alias: true`, остаётся отдельным семейством без оценок (ТЗ v0.6, FR-1). Запись вроде `openai/gpt-chat-latest` алиасом не считается.

## Consequences
- Число семейств получится чуть больше, чем при безусловной очистке дат; зато каждая оценка относится к реально существующей модели.
- Различающиеся цены вариантов отображаются через `price_variants` (конституция, «Семейство модели»).
- Правило дат можно ослабить позже, если сопоставление с бенчмарками покажет, что датированные записи без базы надо объединять.
